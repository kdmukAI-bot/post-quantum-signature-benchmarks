# Post-quantum signature benchmarks on SeedSigner-class hardware

Timings of post-quantum signature schemes on five boards, compared with the hardware
wallet figures Blockstream published. Hash-based schemes: SLH-DSA-SHA2-128s, SPHINCS+
2^40, SHRINCS (B and L), and XMSS 2^10, from Blockstream's code in the Jade fork. Lattice
schemes: ML-DSA (mldsa-native) and FN-DSA (c-fn-dsa). Boards:

- Pi Zero (measured on a Pi Zero W) and Pi Zero 2 W: SeedSigner runs on them today.
- ESP32-P4: the initial target of SeedSigner's port to MicroPython.
- ESP32-S3 and RP2350: smaller chips for a possible stripped-down, ultra-low-cost
  SeedSigner.

Report: <https://kdmukai-bot.github.io/post-quantum-signature-benchmarks/> (results in
`index.html`, methods in `methods.html`, both generated by `scripts/report/` from our run
logs). The run logs are not published: checking a figure means rerunning it on the
hardware, and the report's tables and `results/summary.csv` carry every figure.

## Provenance

The benchmark harness, the measurements, and the report were produced by an AI agent
(Claude) at the direction of GitHub user [kdmukai](https://github.com/kdmukai). The
results have not been independently reviewed.

## Reproduction

Prerequisites: git, Python 3, and Docker. Every board's build runs in a pinned Docker
image: the Pi Zero in `ghcr.io/kdmukai-bot/seedsigner-raspi-lvgl/sdk-armv6:ss-os-0.8.0-81-gbfbd791`
and the Pi Zero 2 W in `ghcr.io/kdmukai-bot/seedsigner-raspi-lvgl/sdk-pi02w:ss-os-0.8.0-81-gbfbd791`
(SeedSigner OS's SDK images), the ESP32 boards in
`ghcr.io/kdmukai-bot/seedsigner-micropython-builder-base:idf-v5.5.5`, all pulled by the
build scripts, and the RP2350 in an image you build once:
`docker build -t pqb-rp2350:sdk2.3.1-gcc14.2 harness/pico/docker`.

```
git clone --recurse-submodules https://github.com/kdmukAI-bot/post-quantum-signature-benchmarks
cd post-quantum-signature-benchmarks
python3 -m venv .venv && .venv/bin/python -m pip install -r requirements.txt
```

Build the benchmark:

- Host: `make -C harness/linux` (the header of `harness/linux/Makefile` lists the Pi Zero
  and Pi Zero 2 W targets and every option).
- ESP32 boards: `scripts/esp_opt_build.sh`; per-round level options in
  `scripts/r2_esp_build_all.sh` and `scripts/r3_esp_build_all.sh`.
- RP2350: `scripts/r4_rp2350_build.sh` in the image built from
  `harness/pico/docker/Dockerfile`; level options in `scripts/r4_rp2350_build_all.sh`.

The run plans, queues, and capture scripts for each round are in `scripts/`; they write
their logs under `results/raw/<device>/<round>/` (ignored by git), with devices `pi0w`,
`pi02w`, `esp32p4`, `esp32s3`, `rp2350`, and `host` (the x86-64 reference outputs the
correctness check compares against). The methods page describes timing, inputs, levels,
and the correctness checks.

With a full set of logs in place, the generator rebuilds the report, checks every summary
figure against its detail table, stops on a mismatch, and names any planned log that is
missing:

```
.venv/bin/python -I scripts/report/fill.py
.venv/bin/python -I scripts/report/build_pages.py
```
